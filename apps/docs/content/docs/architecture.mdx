## The pieces

| Piece | What it does | In the code |
|---|---|---|
| **Web app** | The app, its API (`/api/v1/ask`), and the answers, streamed as the agents work | `apps/web` |
| **Worker** | Reads every file, runs deep searches, makes study sets, runs agents and audio briefs | `apps/worker` |
| **Postgres + pgvector** | Passages with their Nemotron vectors and full-text index, chats, runs, study cards | `packages/db` |
| **Object storage** | Every file and its PDF rendition, so one viewer can highlight any citation | `packages/storage` |
| **Zetaris** | The evidence store: every passage, Zetaris's own reading of every PDF, and the SQL that checks every quote | `packages/zetaris` |
| **Meterless** | H-MEM (your corrections), World Model (which source says what), Markovian (long deep searches) | `packages/meterless`, `packages/agents` |
| **Models** | One place for every model call: a fallback on the other provider, a reserve, a deadline, a rate limit | `packages/models` |

## Where a file goes

1. **Upload or import:** a PDF, Word file, slides, web page, YouTube link, recording, or a Gmail,
   Drive or Notion item.
2. **One PDF for everything:** Gotenberg converts it; scanned pages get OCR; recordings are
   transcribed with ElevenLabs Scribe, cited to the second.
3. **Passages:** split with their page and position, embedded with Nemotron 3.5 Embed, summarised
   with Nemotron 3.5 Lightning.
4. **Into Zetaris:** the passages and the PDF are published; Zetaris reads the PDF itself.
5. **Ready:** only once Zetaris answers for it. From then on, every quote from it is checked there.

## Where it runs

One Coolify server runs the web app, the worker, Postgres, object storage, Gotenberg and this
docs site (a static export), with Zetaris beside them. [konkyo.xyz](https://konkyo.xyz) and
[docs.konkyo.xyz](https://docs.konkyo.xyz) are what's described here. To run your own:
