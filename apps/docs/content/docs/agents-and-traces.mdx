title: The agents and their trace
description: Who does what, with which model, and how to read the trace.
---

| Agent | Does | Model (NVIDIA Nemotron) |
|---|---|---|
| Planner | Stand-alone question, 1–3 searches, comparison flag; reads H-MEM corrections first; replans more broadly when the first search is thin | Nemotron 3 Ultra, thinking off |
| Retriever | Hybrid search: pgvector and Postgres full text, fused by Reciprocal Rank Fusion | Nemotron 3.5 Embed (question as a query, passages as passages) |
| Writer | Cited draft, one finding per sentence; rewrites rejected sentences | Nemotron 3 Ultra, thinking off |
| Verifier | Code check, one Zetaris statement, support judgement; at most two rewrite rounds | Nemotron 3 Ultra, thinking off |
| Analyst | Claims × sources with stances, quotes checked in Zetaris, World Model; places each paper a watch finds against your sources (agrees, disagrees or new, your passage quoted) | Nemotron 3 Ultra, thinking off |
| Scout | Deep search over OpenAlex and Wikipedia, screened in Markovian steps | Nemotron 3.5 Lightning plans; Ultra screens |
| Tutor | Practice items; every answer key checked by the Verifier, every quote in Zetaris | Nemotron 3 Ultra, thinking off |

A call that runs past its usual time is asked again (a hedged request: the first answer wins, the
other is cancelled), and every role has a fallback model for errors, stalls (no answer within 45
seconds, or no first word of a stream within 25; 15 for the Planner, 90 for the Tutor's drafts)
and malformed replies; the switch is logged as `escalated_to_fallback`. A model that refuses
(NVIDIA's free tier answers 429 when it's full) goes to the fallback at once, with no retries, and
is tried second for the next minute. The Verifier, Screener and Grader fall back to
Lightning with thinking on, the Planner to Lightning, the Writer, Analyst and Tutor to Nemotron 3.5
Super. The models were picked by a measured benchmark on NVIDIA's API: Ultra with thinking off
was the only setup to pass every test (0/10 false rejections, 6/6 planted errors caught, 9/9
quotes verbatim); Lightning judged as well only when thinking, and never kept the cited format.
On real practice sets Ultra's drafts passed every check 17 times in 19.

## Reading a trace

Every run writes `logs/<runId>.jsonl`, one JSON line per step:

```json
{"ts":"2026-10-17T12:31:04.118Z","runId":"…","agent":"verifier","step":"verify_0","action":"queried_zetaris","sqlHash":"0cc394679bad","rowsReturned":2,"verdict":"2/2 quotes found","latencyMs":3317}
```

| Field | Meaning |
|---|---|
| `agent`, `step`, `action` | Who did what: `planned`, `hybrid_search`, `broadened_search`, `hybrid_search_broadened`, `not_in_library`, `offered_scout`, `finding_agrees`, `finding_disagrees`, `finding_new`, `queried_zetaris`, `drafted_answer`, `rejected_to_writer`, `revised_sentences`, `approved`, `asserted_world_model`, `read_hmem` |
| `model`, `tokens`, `latencyMs` | Which model, at what cost and speed |
| `sqlHash`, `rowsReturned` | Which Zetaris statement (by hash) and what came back |
| `verdict`, `detail` | The decision, and its reasons |

The app shows the same run as the answer's receipt.
